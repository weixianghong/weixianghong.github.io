上一篇的 Agent 已经会搜文件、改代码、跑测试了。现在假设它改完了，也跑了测试，最后告诉我“全部通过”。我打开日志一看，测试命令退出码确实是 0，但输出里还有一句：一共跑了 0 条测试。

这时候继续换一个更强的模型，可能有帮助。更直接的办法是让运行时把“跑了哪条测试、结果是什么”变成明确的反馈，然后要求有证据才能把活标成完成。围着模型搭的这套东西，通常就叫 **harness**。这里我把它用来指管理上下文、执行工具、记录状态和验证结果的那层应用逻辑。Agent 循环可以由它驱动。[^harness]

## Skill：把同样的交代写一次

我让 Agent 改测试时，经常要说同样几句话：“先看仓库里的说明，跑指定的测试，别把整个项目顺手格式化一遍。跑不了就告诉我卡在哪里。”如果每次都要讲一遍，可以把这套做法写成一个 **Skill**。

拿这个例子来说，Skill 可以告诉模型先找项目规定的测试入口，尽量先复现问题，修改后再跑同一个测试，并报告是否真的收集到了目标用例。如果是 Python 仓库，可能要先检查虚拟环境；如果是另一个项目，具体命令得根据仓库来定。步骤可以复用，判断还得现场做。

以 Agent Skills 的文件约定为例，入口是 `SKILL.md`。运行时可以先只让模型看到 Skill 的名字和简介，需要用时再加载完整说明，附带的脚本、参考资料也按需读取。这样平时不用把几十份操作手册都塞进每次调用。[^skills]

我会把“按什么步骤做”写在 Skill 里，把必须守住的条件交给运行时。比如 Skill 可以要求改完后跑测试，但如果系统要保证“没有通过验证就不能自动合入”，就得真的在合入前检查，或者交给 CI 去挡。光在说明里多写一遍“必须”，挡不住工具调用。

## 它为什么会忘了自己在干什么？

回到改测试的例子。Agent 已经看过几个文件、试了两条命令，还读了很长一段测试输出。到了下一轮，模型能继续干活，是因为应用把需要的信息送进了新的上下文。这里有三样东西容易都被叫成“记忆”：

<div class="inference-table" markdown="1">

| 放在哪里 | 在这次任务里是什么 |
|---|---|
| 当前上下文 | 原始任务、相关代码片段、刚收到的测试结果 |
| 会话记录或任务状态 | 试过哪些命令、改了哪个文件、哪一步还没验证 |
| 跨会话保存的信息 | 这个仓库惯用的测试入口，或用户一贯的改动范围偏好 |

</div>

区别在于，**存下来了，下一轮也未必看得到**。一段日志可以留在会话记录里，需要时再打开；当前上下文只留关键报错和日志的位置。反过来，如果压缩时把“只改一个测试”给丢了，模型接下来真可能把相关测试全改一遍。保存历史有用，但还得决定什么时候取回来。

这里也能接上 [KV Cache](/blogs/inference-kv-cache/) 那篇。前缀缓存省的是重复计算，上下文管理决定的是哪些信息值得继续让模型看。比如工具打了五千行日志，可以只把失败的用例名和关键堆栈放进下一轮，把完整日志留在外面。要压缩已有消息时，即使要重算部分前缀，只要能把任务约束和验证状态留住，这笔账也可能划得来。

## 让每一步有个看得见的结果

对我来说，一个好用的 coding agent 最值钱的地方，是我能分清它**做了什么、验证了什么、还有什么没做**。拿刚才那个“退出码 0，但没跑测试”的例子，运行时能做几件很具体的事。

<figure class="inference-figure">
{% include inference/harness-feedback.svg %}
<figcaption>用测试结果决定下一步。没有收集到目标用例时，应把这条信息交回 Agent 继续排查，或者报告验证受阻。</figcaption>
</figure>

第一是**检查工具结果**。退出码只是一个信号。测试框架能输出结构化报告的话，还可以检查目标用例是否存在、有没有被跳过、是否真的通过。

第二是**把权限放在执行边界**。读仓库、改工作区、推到远端，是三个不同的动作。模型可以提出请求，实际能做哪一个，要由执行环境来判断。重试也得分情况：读文件失败可以再读一遍；如果刚才是发请求更新远端，超时后应该先查状态，因为服务端可能已经执行了。

第三是**保留明确的结束状态**。比如“已修改，目标测试通过”，“已修改，缺少依赖，验证受阻”，或者“没找到足够证据，未修改”。我接手的时候，一眼就能知道还要不要跑一遍，省得从一长串对话里猜它到底做到了哪儿。

回到这两篇的例子：MCP 可以帮我接上文件或 GitHub 工具，Skill 可以把测试流程说清楚，harness 可以记录每一步，并在合适的地方检查结果。真要评价这套东西好不好，我会先看那条最朴素的标准：**用户要修的那个测试修好了吗，怎么知道的？**
